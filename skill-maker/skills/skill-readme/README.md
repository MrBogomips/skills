# skill-readme

Checks and drafts the public `README.md` of a plugin and of every skill it distributes. You get review
notes that name each problem with its file, section and evidence, and, in draft mode, a short README
per component.

## Why

A README written by hand drifts from the code, and one written by a model without checks invents
commands or retells the whole `SKILL.md`. This skill keeps the README short and true: a script checks
the structure and the size, and a separate reviewer checks each statement against the component's
files. Existing content is kept.

## Use cases

### Find what is wrong with an existing README

**Context:** Your plugin has gained an agent and a setting since its README was written.

**Action:** Run `/skill-maker:skill-readme check <plugin folder>`.

**Result:** Review notes in the reply, each finding with its section and line.

### Restructure a README without losing its content

**Context:** A skill README has its own sections, one of them generated by a tool.

**Action:** Run `/skill-maker:skill-readme draft <skill folder> <output folder>`.

**Result:** A draft with the contract sections first and the existing sections kept after them, and
a `review-notes.md` with the questions left for you.

## Usage

```text
/skill-maker:skill-readme check|draft <plugin or skill folder> [output folder]
```

`check` is read-only. `draft` writes to the output folder, never over an existing README; a draft is
applied only when you ask for it. Without a folder, the skill uses the plugin of the working
directory.

The sections a README must have are in [references/contract.md](references/contract.md).

## Requirements

The `skill-maker` plugin, and Python 3.9 or later as `python3`.

## Limitations

- Works on one plugin at a time.
- Checks statements against files, not by running the component.
